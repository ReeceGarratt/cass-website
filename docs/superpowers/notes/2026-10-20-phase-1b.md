- **Carousel speed is configurable through a GitHub variable.** Proposed shape, for 3A to confirm while building:
  - A repository variable `CLIENT_STRIP_LOOP_SECONDS` (Settings → Secrets and variables → Actions → Variables), passed to the build step in `deploy-pages.yml` as `PUBLIC_CLIENT_STRIP_LOOP_SECONDS: ${{ vars.CLIENT_STRIP_LOOP_SECONDS }}`. That's the same `env:` pattern `BASE_PATH` uses.
  - Astro reads it at build time (`import.meta.env.PUBLIC_CLIENT_STRIP_LOOP_SECONDS`) and writes it into the CSS animation duration. **Default 40 seconds per loop** when it's unset or not a positive number: about 40px/s across the 1646px row, a slow drift.
  - It's baked in at build time, so changing it needs a redeploy (re-run the workflow). It isn't a runtime setting.
  - The Cloudflare Workers deploy (D-009) will need the same variable when it replaces Pages.

- **The carousel's WCAG 2.2.2 gap (known and accepted for now).** WCAG 2.2.2 (Pause, Stop, Hide, level A) requires a way to pause content that moves automatically for more than 5 seconds. Hover covers mouse users only, and Reece has ruled out a button for now. *Build without changing the design:* CSS only (the name list duplicated once, the copy `aria-hidden`, a `translateX` keyframe), paused on `:hover` and `:focus-within`, and **static under `prefers-reduced-motion: reduce`** (the row from Figma). None of that is visible in the design. *Revisit:* whether touch and keyboard users need a pause control. Ask Cass if it comes back, and record this as a known accessibility gap when it's numbered.
